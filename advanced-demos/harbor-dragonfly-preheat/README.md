# Harbor + Dragonfly: preheat before the fleet arrives

An advanced, single-terminal companion to **Taking cloud-native offline**.
Harbor is the on-prem registry hub; its own P2P preheat policy seeds Dragonfly
before five cold consumers request Jenkins. Then Harbor stops serving **all
blobs**, including to the seed, while the consumers still obtain identical images.

**Offline spectrum: level 3/4**, using this demo's explicit scale:
1. opportunistic cache; 2. prefetched artifacts with upstream fallback;
3. verified operation without external egress; 4. independently provisioned,
physically disconnected environment with a complete update/trust lifecycle.
This demonstrates level 3, not an offline installation of the host.

## Architecture

```text
CONNECTED (host only)
  GitHub releases ---> official Harbor configuration generator
  Docker Hub/Quay ---> pinned images in host Docker engine
                             |
                 Jenkins export and authenticated push
                             v
  +---------- Docker --internal network: offline-preheat-airgap -----------+
  |                                                                      |
  | harbor:8080 [NGINX gate] ---> Harbor HTTP proxy/core/registry           |
  |         |                       |                                    |
  |         | manifests/token       | Harbor manual P2P preheat policy    |
  |         |                       v                                    |
  |         |                    manager ---> scheduler                   |
  |         |                       |             |                       |
  |         |                    MariaDB/Redis    v                       |
  |         |                                  seed cache                |
  |         |                                  /  |  \                   |
  |         v                                 v   v   v                  |
  |    peer1 ... peer5 <--------- pieces between peers ---------->        |
  |      each has a skopeo client sharing its network namespace           |
  +----------------------------------------------------------------------+
AIR-GAPPED: no image pulls/builds/downloads from the internet
  1. Five concurrent direct copies from Harbor (baseline).
  2. Gate returns 403 for every blob, but still serves metadata/auth.
  3. Five NEW peers concurrently copy all blobs from the seeded swarm.
```

Harbor's generated services are a second Compose project on the **same internal
network**. The official generator provides the registry/core/jobservice/database
wiring; the script removes global container names, syslog coupling, published
ports, automatic image pulls, and adds core readiness gates. No host daemon
configuration, host firewall, Kubernetes cluster or privileged container is needed.

## Prerequisites

- Linux **amd64**, rootful Docker Engine, Compose with `--wait` and JSON `config`
  output, Bash 5+, curl, jq 1.7+, tar, GNU coreutils. Exact tested versions below.
- Docker socket access for the operator. The CONNECTED export briefly mounts the
  socket in skopeo; this is root-equivalent access. Never give it to untrusted code.
- At least 8 CPU cores, 12 GiB available RAM and **25 GiB free disk before the first
  run**; more is advisable on a shared machine. Ten destination copies plus six
  peer caches are intentionally independent.
- Access to Docker Hub, Quay and GitHub releases during CONNECTED.
- Reserve Compose projects `offline-preheat` and `offline-preheat-harbor`, and
  network `offline-preheat-airgap`. Do not run two copies concurrently.

**Disposable sandbox only.** HTTP, anonymous reads of one public project, an
unauthenticated Dragonfly control plane, and historical software are deliberate.
Credentials are generated per run in ignored local state, never committed. Do not
reuse this as a production registry deployment.

The engine reports **445,294,445 image bytes** (~445 MB). The amd64 image pushed

authenticated `/oapi/v1/jobs` API; upgrading one side blindly is not compatible.

## Run: one terminal, two explicit phases

From this directory:

```bash
./scripts/run-demo.sh
```

The run is repeatable: it tears down **only its own projects**, removes old runtime
data, generates new credentials, and recreates cold peers/destinations. It does
not prune shared Docker images or touch other demos. Existing evidence is
overwritten by the next successful run; copy it elsewhere before another run
if needed. After a failure, inspect timestamps: some evidence may be from the
previous run.

### CONNECTED

1. Pull every pinned image, download the official Harbor online installer, and
   generate HTTP-only Harbor configuration locally. The generator runs with
   `--network none`, without privileged mode or a mount of the host root.
2. Create the internal network and bring up both Compose projects. Poll actual
   gRPC health; manager/discovery refresh is bounded to avoid a ten-minute
   negative discovery cache during bootstrap.
3. Create public project `fleet`; export Jenkins from the Docker daemon into
   local files and push it to Harbor using a temporary auth file. Anonymous
   consumers cannot push.
4. Register Harbor provider `dragonfly` at `http://manager:8080`, create manual
   policy `jenkins` selecting repository `jenkins` and the exact tag, and trigger
   it through **Harbor**, not a synthetic manager request.
5. Wait for `Success` **and exactly one successful task**. Capture seed metrics;
   origin byte count must be nonzero. No consumer peer exists yet.

### AIR-GAPPED

1. Check every Compose container's network attachments: it must be running,
   unprivileged, attached only to the internal network. Test external TCP 80 and
   443 from **each container's network namespace** using literal IP `1.1.1.1`;
   only connection-denied/timeout exits are accepted.
2. Run five simultaneous cold, direct Harbor-to-directory skopeo copies.
3. Reload the gate to return 403 for **all** blob URLs, for everyone. Probe a real
   layer and require an actual 403. Manifests and local token issuance stay up.
4. Start five fresh dfdaemons, each with its own cache. For each, start a skopeo
   client in that peer's network namespace with HTTP proxy `127.0.0.1:65001`.
   Each client copies the same image into its own new destination.
5. Verify every layer/config SHA-256 and byte-identical manifests for **all ten**
   copies. Recheck isolation, capture source/peer metrics and gateway logs.
6. Require zero successful origin blob bytes after cutover, unchanged seed
   origin bytes equal to the image payload, and exactly 13 P2P blob requests
   per consumer for this image. Produce timings and distribution reports.

`DEMO_SLEEP_SECONDS=0 ./scripts/run-demo.sh` removes narration pauses. `clear`
is used only on an interactive terminal with `TERM`; redirected runs remain
readable. All container launches in AIR-GAPPED use `--pull never`; no packages
are installed or images built in that phase.

## Expected output and measurement

The script prints phase banners, real preheat status, per-namespace blocked
probes, ten timing rows, a distribution table, and measured total runtime.
Any failed command, copy, digest, origin or isolation assertion exits nonzero.

The final complete verified run took **182 seconds** with tool images already cached.
Cold external downloads are not included in that figure. Five-way concurrent
copies in that run:

| Consumer | Direct Harbor (ms) | Dragonfly (ms), Harbor blobs blocked |
| --- | ---: | ---: |
| 1 | 7,576 | 6,184 |
| 2 | 7,421 | 6,184 |
| 3 | 7,578 | 6,181 |
| 4 | 7,433 | 6,220 |
| 5 | 7,575 | 6,180 |
| Mean | 7,516.6 | 6,189.8 |

**No general speedup is claimed.** This single-host test shares disk, bridge and
CPU. An earlier complete run took 193 seconds and measured 11,959.0 ms direct
versus 12,856.6 ms P2P: P2P overhead can exceed direct reads. The final rerun also
verified teardown/reset/recreation idempotency. The reliable efficiency is offload:

| Node | P2P proxy blob requests | Bytes uploaded to peers |
| --- | ---: | ---: |
| seed | 0 | 736,011,202 |
| peer1 | 13 | 32,919,990 |
| peer2 | 13 | 96,759,016 |
| peer3 | 13 | 191,308,375 |
| peer4 | 13 | 0 |
| peer5 | 13 | 209,324,892 |

The direct baseline fetched 5 x 253,264,695 = **1,266,323,475 payload bytes** from
Harbor. Preheat fetched the image once. During the P2P arm Harbor served **zero**
successful blob bytes, and seed origin traffic stayed at **253,264,695 bytes**.
Consumers served one another; the seed was not the sole distributor.
Retries and scheduling can change distribution on another run. A peer can
receive the entire image without being chosen to upload any pieces (peer4 here).

Timing surrounds `docker run ... skopeo copy`, excluding digest rechecks; it
includes client/container startup, local auth/manifest fetches, transfer and
destination writes, not only network time. Each arm is five concurrent jobs;
the peers are cold but Harbor and the kernel's page cache are warm. These are
image transport pulls, **not Docker/containerd unpack/start timings**. Jenkins
itself is not started and no plugins are downloaded.

## Troubleshooting

- **Preheat succeeds, blocked-source copies fail:** do not unblock the origin to
  make the demo green. Check seed eviction, canonical `http://harbor:8080` URLs,
  task IDs, scheduler logs and source counters. An early test hit disk-pressure
  GC at 95% usage and correctly failed. The demo now uses 1 GiB/99% thresholds
  so a nearly full shared sandbox does not immediately discard its small cache.
  These are **demo-only** limits; provision dedicated storage and sensible
  watermarks in production. Free space first if near either threshold.
- **Startup fails:** inspect [artifacts/dragonfly.log](artifacts/dragonfly.log)
  and [artifacts/harbor.log](artifacts/harbor.log). The scripts do not retry
  broken services forever. Manager precedes scheduler; scheduler precedes seed;
  Harbor jobservice waits for core health.
- **413 uploading Jenkins:** retain `client_max_body_size 0` and streaming
  request forwarding in [config/gateway.conf](config/gateway.conf).
- **Harbor says `no underlying filters`:** use both repository and tag selectors;
  an empty filter list is not a match-all policy on this Harbor version.
- **Generated env files unreadable:** prepare creates root-owned files; the
  orchestrator changes ownership of only imported `env` files. It deliberately
  preserves Harbor's runtime file/database ownership. Do not run the whole
  demo with sudo just to sidestep this.
- **Cannot open Harbor from the host:** intentional; no ports are published.
  Use an in-network API client, for example:

  ```bash
  bash -c 'source scripts/common.sh; api /p2p/preheat/instances'
  ```

  This also avoids relying on host-published ports on internal networks.
- **403 on a blob after completion:** expected. Start the complete orchestrator
  again for a clean connected preparation/baseline; repeated benchmark calls
  intentionally refuse existing (warm) destination directories.
- **Interrupted run:** diagnostics and resources remain for inspection.
  Run cleanup below; then restart. Do not globally prune Docker on a shared host.

## Where network is still required

- CONNECTED needs GitHub for the installer and Docker Hub/Quay for images.
  Export/import the pinned engine images and installer separately to provision
  a physically disconnected host; that bootstrap is outside this demo's claim.
- AIR-GAPPED still needs **local** networking: registry manifest/token services,
  Dragonfly manager/scheduler, databases, seed and peer piece transfer. Here
  "no internet" does not mean "no packets": blocking all local traffic would
  make registry/P2P distribution impossible.
- This uses a local Harbor project, **not a Harbor proxy-cache project**. No
  Docker Hub mirror configuration, scanner database, external IdP, telemetry
  service, remote logging endpoint or public DNS lookup is needed offline.
- Docker's internal bridge prevents external forwarding. Verification checks
  attachment structure plus negative TCP probes, not an exhaustive protocol
  penetration test or packet-by-packet capture. The host/Docker daemon remain
  connected; a privileged host user could reconnect containers or bypass the
  gate using internal service addresses. This is reproducibility isolation,
  not a hostile-tenant security boundary. Do not change routes/attachments
  between verification and the workload.
- The failed egress probes deliberately attempt external connections; none may
  succeed. They use literal IPs to avoid DNS-forwarder leakage. Runtime services
  resolve only Docker-local names. HTTP integrity here is checked using the
  connected-phase manifest, not signatures rooted in offline trust material.

## Known limitations

- Full demo tested on rootful Linux amd64 only; rootless Docker, Docker Desktop,
  ARM64 and real multi-host fleets are **untested**.
- Historical pins have known lifecycle/security risks. Upgrade and harden both
  sides, enable TLS/auth, audit advisories and validate their API contract before
  any production use. HTTP-only is explicitly requested for this sandbox.
- The seed must retain the image: peer caches are disposable container writable
  layers, not a replacement for Harbor's durable registry data. No peer death,
  eviction, token expiry or multi-hour offline survival claim is made.
- Source-blocking is enforced on the canonical registry gateway, not by stopping
  Harbor; auth and manifests are deliberately retained. There is no central
  bandwidth cap, so the timing table is not a simulated WAN-speed benchmark.
- SHA-256 checks prove transport against the prepared manifest, not that Jenkins
  or its dependencies can be updated or operated offline.

## Cleanup

```bash
./scripts/cleanup.sh          # containers, anonymous volumes and internal network
./scripts/cleanup.sh --reset  # also generated credentials, registry data and pulls
```

Both are idempotent. Evidence and the cached installer remain. Shared images are
not pruned. The reset uses the already-pulled skopeo image with `--network none`
to delete only named demo-owned directories/files, including root-owned data.
Local credentials, generated internal keys/certificates and auth material stay
under ignored [.state/](.state/); [artifacts/](artifacts/) is ignored too.
Never commit either, even though Harbor is configured for HTTP.

## Future tooling

- Newer Harbor/Dragonfly integrations use scoped access tokens and job APIs,
  richer preheat policies, and newer clients. Migration should test URL/task
  identity, auth, cache expiry and success semantics as one contract.
- Kubernetes-native peer placement and topology-aware scheduling can place
  seeds per rack/zone and reduce cross-site traffic. Validate on multiple hosts
  with bandwidth-controlled origins before extrapolating these measurements.
- OCI referrers, signatures, SBOMs and offline verification bundles need their
  own prefetch/retention/trust lifecycle; image layers alone are not a complete
  software delivery air gap.
- Persisted P2P caches and observability should expose what is retained, why it
  was evicted and which source served each byte. Preheat success is a moment in
  time, not proof that a future offline pull can still succeed.
